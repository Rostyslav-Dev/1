# RK | Портфоліо для локального бізнесу

Готовий статичний проєкт. Основна мова - українська; англійська версія у `en/index.html`. Два нові сайти - демонстраційні, не реальні компанії. Старі AURÉA і Massage збережено як авторські концепти, додано плашку автора. Нічого не опубліковано автоматично.

## Структура

- `index.html`, `en/index.html` - повні сторінки портфоліо.
- `style.css`, `app.js` - дизайн, мобільне меню, форма.
- `projects/barbershop/index.html`, `style.css`, `app.js` - NOIR & CO.
- `projects/detailing/index.html`, `style.css`, `app.js` - APEX DETAIL.
- `projects/aurea/`, `projects/massage/` - наявні демо, їхні оригінальні стилі й сценарії.
- `assets/` - оригінальні візуали, SVG favicon, нові WebP OG-картки.
- `sitemap.xml`, `robots.txt` - SEO.

## Запуск

Розпакуйте ZIP, відкрийте папку `portfolio-main` та перенесіть її вміст у корінь свого репозиторію GitHub (не додавайте ще одну вкладену папку). Для локальної перевірки: `python3 -m http.server 8000`, потім відкрийте `http://localhost:8000/`. Залишено canonical з вихідного проєкту: `https://rostyslav-dev.github.io/portfolio/`. Якщо фактична адреса інша, замініть цей префікс в усіх HTML, sitemap та robots; перевірте налаштування Pages. Не видаляйте старий репозиторій без резервної копії.

## Заявки: без секретів у браузері

Поки `data-endpoint` порожній, форма готує текст, дає копіювати його і відкрити Telegram або email. Вона **не стверджує, що заявка надіслана**. Для запуску через сервіс форм створіть форму у Formspree чи іншому сервісі, який приймає JSON POST з браузера, додайте його HTTPS endpoint в обидва HTML-файли. Увімкніть підтвердження адреси отримувача, антиспам та дозволені домени. Для Telegram використайте серверну автоматизацію (наприклад, webhook сервісу -> Make -> Telegram Bot) або власну serverless-функцію. Bot token і chat ID зберігайте у секретах на сервері, не в HTML/JS. Функція повинна обмежувати частоту, перевіряти поля/розмір, дозволені origins, захищати від спаму й повертати 2xx тільки після доставки. Перед публікацією протестуйте успіх і помилку та додайте політику обробки даних. Реальні інтеграції та CRM не налаштовані.

## SEO

Один h1 у кожній із 4 нових сторінок; мета-теги, canonical, Open Graph, WebP OG-картки, двосторонній hreflang `uk`, `en`, `x-default`; ProfessionalService для портфоліо. Нові демо мають WebPage JSON-LD з `about: HairSalon` або `AutoRepair`, де явно зазначено вигаданий бізнес. Усі 4 демонстрації залишено `noindex,follow`, щоб не видавати вигадані компанії за реальні в Google. Через це sitemap містить лише дві індексовані мовні сторінки, а не noindex-демо. Це навмисне рішення. GitHub Pages project site може потребувати robots.txt на корені домену; перевірте після публікації.

## Фото / відео

- Портфоліо: професійний портрет біля ноутбука, нейтральне тло, справжні скриншоти готових сайтів (1440×900 і мобільні). Не використовуйте чужі скриншоти як свої.
- Барбершоп: широкий кадр інтер’єру з теплим боковим світлом, вертикальні портрети майстрів, крупні плани волосся і бороди, фото інструментів; однакова кольорокорекція.
- Детейлінг: широкий кадр авто з бічною смугою світла, макро ЛФП та процесу нанесення покриття. Пари до/після - один автомобіль, та сама позиція камери, фокус, світло і експозиція; без ретуші, яка підміняє результат.
- WebP, орієнтир 1600–1920 px hero / 800–1000 px картки, стискання під візуальну якість; додавайте справжні `width`/`height`, `alt`, `loading="lazy"` для позаекранних зображень. Hero завантажуйте без lazy-loading. Відео необов’язкове, коротке, без автоматичного звуку, з постером та ручним запуском.

## Що змінено / перевірено

Прибрано 6 довгих вступних екранів і космічну навігацію. Перший екран одразу пояснює результат і веде до заявки. Чотири картки однакового формату; AI-концепти перенесено вниз. Дві нові незалежні стилістики: теплий класичний барбершоп і холодний технологічний детейлінг. Чисті HTML/CSS/JS, без нових бібліотек. Функціонал запису й калькулятора не надсилає дані. Додано видимий focus, reduced-motion, мобільні кнопки, семантику.

Перевірено синтаксис нових JS (`node --check`), рендеринг 4 нових сторінок у Chromium на 360 і 1440 px з інлайнованими ресурсами (без горизонтального переповнення, JS помилок); раніше перевірено 768 px. Пройшли сценарії мобільного меню, підготовки заявки, 3-крокового запису, калькулятора, слайдера й демозаявки. Через обмеження навігації браузера локальний HTTP / file URL заблоковано, тому не було повного наскрізного тесту переходів, живої форми, Lighthouse або Safari/iOS. Попередні два демо збережено, їхні старі анімації та інші особливості не переписано. Не заявляємо підтверджені Lighthouse 90+ чи повний аудит WCAG. Перед публікацією перевірте всі сторінки на смартфоні, запустіть Lighthouse у Chrome DevTools (Mobile) і протестуйте реальну доставку заявки.
